Types of Parent-Child Relationships in NetSuite
1. One-to-Many (1:M) Relationships
A single parent record can have multiple child records.
Examples:
Customer (Parent) → Contacts (Children)
Vendor (Parent) → Vendor Addresses (Children)
Employee (Parent) → Expense Reports (Children)
2. Many-to-Many (M:M) Relationships
Multiple parent records can be associated with multiple child records.
Examples:
Items ↔ Locations (Items can be available in multiple locations, and locations can have multiple items).
Employees ↔ Projects (Employees can work on multiple projects, and projects can have multiple employees).
3. One-to-One (1:1) Relationships
A single parent record is linked to a single child record.
Examples:
User (Parent) → Employee (Child) (Each user has one employee record).
Subsidiary (Parent) → Tax Nexus (Child) (Each subsidiary has one tax nexus).
4. Hierarchical (Parent-Child within the Same Record Type)
A record can be both a parent and a child.
Examples:
Subsidiary Hierarchy (Parent Subsidiary → Child Subsidiary).
Employee Hierarchy (Manager → Subordinates).
Accounts in Chart of Accounts (Parent Account → Sub-Accounts).

Comparison: Token-Based Authentication (TBA) vs. OAuth 2.0
Feature	        Token-Based Authentication (TBA)	       OAuth 2.0
Security Level	Secure, but uses static tokens	      More secure, uses short-lived tokens
Token Expiry	No expiry (unless revoked)	          Tokens expire & require renewal
Use Case	Internal applications, SuiteScript	        External applications, mobile apps
API Compatibility	SuiteTalk (SOAP), RESTlets,SuiteScript	REST Web Services, SuiteTalk (SOAP)
Complexity	         Easier to implement	                             More complex setup
Authentication Type	    Static tokens	                           Dynamic token exchange
Best Practices for NetSuite API Authentication
✅ Use OAuth 2.0 for high-security integrations and external applications.
✅ Use Token-Based Authentication (TBA) for internal apps and SuiteScripts.
✅ Never share or expose API credentials in public repositories or logs.
✅ Rotate tokens periodically to enhance security.
